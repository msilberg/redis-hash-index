## Codebase Patterns

Seeded from the specification before the first iteration. Add to this section whenever you learn
something general and reusable — not story-specific details.

- Read `tasks/US-XXX.md` for the story you are on before touching code; `prd.json` holds only the
  acceptance criteria, the reasoning is in the task file.
- `docs/REDIS-SCHEMA.md` is the contract shared by all three services. Change it in one place or
  the demo silently stops proving anything.
- `SADD` creates a PERSISTENT key: `EXPIRE ... GT` alone will never set an expiry. Use `NX` then `GT`.
- Invalidation deletes values BEFORE removing index references, so a failed run is retry-safe.
- `SREM` the members you observed; never `DEL` the index set, or you discard concurrent writes.
- The v1 legacy pattern is `*::<userId>::*` — both delimiters, or it matches the index key too.
- Redis runs with `--maxmemory-policy noeviction`. If it evicts the fixture, the benchmark lies.
- Every Redis pipeline reply must be inspected. A silently dropped `SET` shrinks the keyspace and
  flatters the wrong side of the comparison.
- This dev machine has NO local `redis-cli`. Use `docker compose exec -T redis redis-cli ...`
  (or `docker run --rm --network host redis:7-alpine redis-cli -h localhost ...`) in scripts and
  self-checks instead of assuming a host binary.
- npm workspaces: root `package.json` has `workspaces: [packages/cache, services/*]`, each workspace
  has its own `tsconfig.json` extending `tsconfig.base.json` and a `typecheck` script. `make typecheck`
  / `make test` fan out with `npm run <x> --workspaces --if-present`.
- `make up` waits for health via `docker inspect --format '{{.State.Health.Status}}'` on
  `docker compose ps -q` — no `jq` dependency.
