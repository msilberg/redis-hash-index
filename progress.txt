## Codebase Patterns

Seeded from the specification before the first iteration. Add to this section whenever you learn
something general and reusable — not story-specific details.

- Read `tasks/US-XXX.md` for the story you are on before touching code; `prd.json` holds only the
  acceptance criteria, the reasoning is in the task file.
- `docs/REDIS-SCHEMA.md` is the contract shared by all three services. Change it in one place or
  the demo silently stops proving anything.
- `SADD` creates a PERSISTENT key: `EXPIRE ... GT` alone will never set an expiry. Use `NX` then `GT`.
- Invalidation deletes values BEFORE removing index references, so a failed run is retry-safe.
- `SREM` the members you observed; never `DEL` the index set, or you discard concurrent writes.
- The v1 legacy pattern is `*::<userId>::*` — both delimiters, or it matches the index key too.
- Redis runs with `--maxmemory-policy noeviction`. If it evicts the fixture, the benchmark lies.
- Every Redis pipeline reply must be inspected. A silently dropped `SET` shrinks the keyspace and
  flatters the wrong side of the comparison.
- This dev machine has NO local `redis-cli`. Use `docker compose exec -T redis redis-cli ...`
  (or `docker run --rm --network host redis:7-alpine redis-cli -h localhost ...`) in scripts and
  self-checks instead of assuming a host binary.
- npm workspaces: root `package.json` has `workspaces: [packages/cache, services/*]`, each workspace
  has its own `tsconfig.json` extending `tsconfig.base.json` and a `typecheck` script. `make typecheck`
  / `make test` fan out with `npm run <x> --workspaces --if-present`.
- `make up` waits for health via `docker inspect --format '{{.State.Health.Status}}'` on
  `docker compose ps -q` — no `jq` dependency.
- Tests run on `node --import tsx --test "src/**/*.test.ts"` (Node 24, tsx devDep). Use `node:test` +
  `node:assert/strict`. `make test` now does `docker compose up -d redis` first — every service's
  tests need a real Redis, per the spec (no mocks).
- Import sibling modules WITHOUT a `.js` extension (`./index`), tsconfig uses `moduleResolution: node`.
- Consumers of `packages/cache` pass their ioredis client where `RedisClient` is expected and cast
  (`redis as unknown as RedisClient`) — the narrow interface is intentional, don't widen it.
- `EntityIndex.parse` returns `null` for a foreign/malformed key (never throws); `indexKeyFor` and
  `register` throw on bad segments / unknown category.

## 2026-09-09 - US-002
- Implemented `packages/cache` — the shared `EntityIndex` (class) with `indexKeyFor`, `parse`,
  `register`, `invalidateEntities`, `prune`, plus a narrow `RedisClient` / `RedisMulti` /
  `RedisPipeline` interface listing only the commands used.
  - `register`: one MULTI — `SADD`, `EXPIRE ttl NX`, `EXPIRE ttl GT` — every reply tuple inspected;
    returns whether the member was newly added. TTL validated as whole seconds 1..2592000 BEFORE
    any write (rejected call writes nothing).
  - `invalidateEntities`: per entity `SMEMBERS` -> `UNLINK` values (batched, default 500) ->
    `SREM` observed members (batched). Never `DEL`s the set. Deletes every member unconditionally,
    no timestamp filter. Entities processed with bounded concurrency (default 4).
  - `prune`: pipelined `EXISTS` per member, `SREM` the missing ones. Maintenance only, not the
    delete path.
  - `parse` is structural + segment regex `[A-Za-z0-9_.-]+` + category check; returns null, never
    throws. `indexKeyFor` throws on a bad segment or unknown category.
- Tests (`src/index.test.ts`, `node:test` + real Redis on DB 15): key building / parse-null cases;
  NX+GT sets then extends but never shortens; rejected TTL writes nothing; full invalidate removes
  values + refs; injected `UNLINK` failure leaves the index intact and a retry finishes; a member
  added between SMEMBERS and SREM survives; 200,000 members invalidate without a RangeError
  (proves batching, not spreading); prune drops dead refs only. 12/12 pass.
- Files changed: packages/cache/{src/index.ts,src/index.test.ts,package.json,CLAUDE.md},
  Makefile (test target now brings up redis), package-lock.json.
- Self-check executed: `make typecheck` exit 0; `make test` -> 12 pass / 0 fail.
- **Learnings for future iterations:**
  - `EXPIRE key ttl 'NX'` / `'GT'` works through ioredis `multi()` untyped-passthrough; the narrow
    `RedisMulti.expire(key, seconds, 'NX'|'GT')` signature is enough and ioredis is cast in tests.
  - `redis.multi().exec()` resolves to `[err, reply][] | null`; `null` means EXECABORT — treat as
    an error. A queued command that fails at runtime still shows up as `[err, ...]` in the array,
    Redis does NOT roll the rest back.
  - The 200k-member test takes ~2.3s against local compose Redis; keep an eye on total test time
    as more services add real-Redis tests.
