## Codebase Patterns

- Fixture writes go through `EntityIndex.registerMany` with values, using the same NX/GT logic
  as `register`. Each bounded MULTI includes SET EX and registration; runtime errors do not roll back.
- `invalidateEntities` returns per-entity failures in `incomplete`; callers must inspect it.
  Counters include acknowledged partial work, and the entities count includes only successes.
- `prune` uses SSCAN pages: COUNT is a hint, cursors may yield empty pages or duplicate members.
  Keep per-page checks/removals bounded and count observations rather than unique members.

- For the 1 Hz chart, request `getContext("2d", { willReadFrequently: true })` to prefer
  software rendering. Chrome's accelerated canvas failed to display the chart on this machine;
  switching the context restored full redraws. Verify canvas changes visually in Chrome.

- `@Cache` resolves its strategies from a module-level registry at CALL time: every process that
  calls a decorated method (service bootstrap, each test file) must `configureCache(...)` first, or
  the call throws. The decorator builds keys from arguments — call `(userId, { v: N })` for the
  fixture's `{"v":N}` records.
- The fixture has two writers that must agree byte-for-byte: bulk (`registerMany` pipelines) and
  test-api's `@Cache` filling from mock-billing. Both build records via `fixture.recordsFor` and
  serialise via `serializeSubscription`. Keep test-api's `chain.test.ts` and `make verify` step 6 green.
- Grep self-checks that forbid a name will still match the story spec describing it (`tasks/US-XXX.md`,
  prd.json AC text). Don't rewrite specs to satisfy a grep; report the residual matches.

- npm runs workspace `prepare` scripts IN PARALLEL. A workspace package that compiles against another
  workspace's `dist/` cannot use `prepare` — `packages/fixture` has none; `make packages` (a prereq of
  typecheck/test) builds cache then fixture, and consuming Dockerfiles `RUN npm run build --workspace
  @redis-hash-index/fixture` after `npm ci`. Local typecheck alone won't catch this — `make up` did.
- Services share code through `packages/*`, never by importing another service's workspace.
- test-api has ONE route, `/subscription/:userId`, in two modes that must stay distinct: the default
  `@Cache` read-through, and `?fill=false` (SMEMBERS+MGET probe, polled by the runner and verify) which
  must never fill — a filling probe refills what an eviction removes. (`/entitlement` retired in US-012.)
- UI changes CAN be verified in a browser here: `google-chrome --headless=new --screenshot=… --window-size=1400,1000
  --virtual-time-budget=5000 http://localhost:3000/` for a mid-run page (history frame). To capture a state
  that only a live page sees (e.g. after Stop), drive Chrome over CDP (`--remote-debugging-port`, Node's
  global WebSocket, `Page.captureScreenshot`), then Read the PNG.

- The fill chain is benchmark → test-api → mock-billing, all HTTP. benchmark's `Seeder` takes a
  `LazyFiller` (`TestApiFiller` in prod; tests inject an in-process fake). `seeder.start()` is ASYNC
  (seed-value check first) — attach `once(seeder,"done")` before `await seeder.start()`.
- A new workspace must be added to EVERY Dockerfile's build stage as `COPY <ws>/package.json`, or
  `npm ci` in the other images fails against the lockfile.
- Compare expiries with `PEXPIRETIME` (absolute), not two `PTTL` reads — sequential PTTLs drift by a
  millisecond and flake "index outlives value" assertions.
- `tsc` never deletes stale `dist/` files: after moving a module out of a package, `rm -rf dist`, or
  consumers still resolve the old export locally (Docker builds are clean and won't show it).

  - `register`: one MULTI — `SADD`, `EXPIRE ttl NX`, `EXPIRE ttl GT` — every reply tuple inspected;

    delete path.

    throws. `indexKeyFor` throws on a bad segment or unknown category.
