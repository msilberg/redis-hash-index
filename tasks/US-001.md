# US-001 — Compose skeleton, Redis, and the shared toolchain

## Why this comes first

Every later story needs somewhere to run and a single command that proves the stack is alive.
Get the workspace layout wrong now and you will fight it for seven more iterations.

## Layout to create

```
docker-compose.yml
Makefile
package.json                 # npm workspaces root, private: true
tsconfig.base.json
packages/cache/              # US-002
services/test-api/           # US-003
services/webhook/            # US-004
services/benchmark/          # US-005..007
```

## Redis service

```yaml
redis:
  image: redis:7-alpine
  command: ["redis-server","--maxmemory-policy","noeviction","--save","","--appendonly","no"]
  ports: ["6379:6379"]
  healthcheck:
    test: ["CMD","redis-cli","ping"]
    interval: 5s
    timeout: 3s
    retries: 10
```

`noeviction` is not optional. If Redis evicts fixture keys under memory pressure the keyspace
shrinks, the scan gets faster, and the demo quietly starts reporting a result that isn't true.

## tsconfig.base.json

`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`,
target `ES2022`, module `commonjs`, `declaration: true`.

## Makefile targets

| Target | Does |
|---|---|
| `up` | `docker compose up -d --build` then waits for healthy |
| `down` | `docker compose down -v` |
| `logs` | `docker compose logs -f --tail=100` |
| `typecheck` | `tsc --noEmit` across all workspaces |
| `test` | run whatever tests exist; must exit 0 when there are none yet |
| `seed` | `curl -XPOST localhost:3000/api/seed` (may 404 until US-005 — that is fine now) |
| `reset` | `curl -XPOST localhost:3000/api/seed/reset` |
| `verify` | full end-to-end check (US-008) |

## Self-check before marking this story done

```bash
make up
docker compose ps                  # redis healthy
redis-cli -h localhost ping        # PONG
make typecheck                     # exit 0
make down
```
