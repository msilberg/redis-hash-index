# US-006 — the run driver

## The shape of a run

```
t=0s    start polling test-api once per second with a random seeded user id
t=1s    POST BATCH_USERS ids to the webhook (v1 or v2) — one second of quiet baseline first
t=1s+   keep polling and streaming samples until stopped
```

That one-second baseline matters more than it looks: without it the chart opens mid-catastrophe
and there is nothing to compare the spike against.

## Choosing the users

Draw both the polled id and the eviction batch from the seeded id space so they always exist.
Poll a user that is **in** the eviction batch, so the chart also shows the cache going cold — but
the headline is the latency, not the miss.

## Sample frames

One per poll, pushed to every connected WebSocket client:

```jsonc
{ "t":"sample", "runId":"…", "mode":"v1", "ts":1757400000000, "elapsedSec":12,
  "latencyMs":11040.2, "serverLatencyMs":11038.9, "ok":true,
  "job": {"processed":1,"total":1000,"state":"running"} }
```

`latencyMs` is the HTTP round trip the driver measured; `serverLatencyMs` is what test-api reported
for the Redis call alone. Keep both — the gap is small and showing it is honest.

**A poll that times out is data, not an error.** Use a generous timeout (30 s), and on timeout emit
a sample with `ok:false` and the elapsed time rather than dropping the frame. A gap in the chart
during the worst moment would be the exact opposite of the point.

## Stopping

`POST /api/run/stop` clears the interval **and** calls `POST /jobs/:id/stop` on the webhook.
Stopping the poller alone would leave a v1 job grinding through the keyspace for hours.

Only one run at a time: a second `POST /api/run` while one is active returns 409.

## History

Keep the current run's samples in memory (cap ~3,600). A client that connects or reloads mid-run
receives `{t:'history', samples:[…]}` first so the chart redraws instead of starting blank.

## Self-check

```bash
SEED_KEYS=50000 make up && curl -s -XPOST localhost:3000/api/seed && sleep 30
curl -s -XPOST localhost:3000/api/run -H 'content-type: application/json' -d '{"mode":"v2"}'
# connect a websocket client (wscat or a tiny node script) and confirm ~1 sample/second
curl -s -XPOST localhost:3000/api/run -H 'content-type: application/json' -d '{"mode":"v1"}'  # 409
curl -s -XPOST localhost:3000/api/run/stop
curl -s localhost:3002/jobs/<jobId> | jq .state    # "stopped"
make typecheck && make test
```
