# US-003 — test-api, the innocent bystander

## Its entire job

Be a normal service that reads the cache and reports how long Redis took, so that when the webhook
blocks the server we can see it happen to somebody who did nothing wrong.

**It must have its own Redis connection.** Sharing a client with another service would hide the
effect inside client-side queueing rather than showing it as server-side blocking.

**It must never call `KEYS` or `SCAN`.** Not even in an admin route. Grep for it before you commit.

## `GET /entitlement/:userId`

```ts
const started = process.hrtime.bigint();
const members = await redis.smembers(indexKeyFor(TENANT, CATEGORY, userId));
const values  = members.length ? await redis.mget(...members) : [];
const latencyMs = Number(process.hrtime.bigint() - started) / 1e6;
```

Respond `{ userId, hit: values.some(Boolean), variants: values.filter(Boolean).length, latencyMs }`.

`hit: false` after invalidation is the correct, expected answer. Do not treat it as an error and do
not fall back to a scan.

Validate `:userId` against `^u_\d{7}$` and return 400 otherwise.

## Wiring

Port 3001, `GET /health` → `{ok:true}`, Dockerfile (node:22-alpine, multi-stage, production deps
only), compose service with a healthcheck and `depends_on: redis: condition: service_healthy`.

## Self-check

```bash
make up
curl -s localhost:3001/health                        # {"ok":true}
curl -s localhost:3001/entitlement/u_0000001 | jq    # 200, latencyMs present
curl -s -o /dev/null -w '%{http_code}' localhost:3001/entitlement/bogus   # 400
grep -rn "KEYS\|scan(" services/test-api/src         # no matches
make typecheck
```
