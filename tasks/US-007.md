# US-007 — the live UI

## One page, no build step

`GET /` serves a single self-contained HTML file. No bundler, no framework, no npm install to
render a chart. Draw it on a `<canvas>` in plain JS — it is one line series, and a dependency-free
page is one fewer thing that can rot between now and whenever someone clones this.

## The chart

- x: seconds since run start. y: `latencyMs`.
- **y MUST be logarithmic.** The two modes differ by roughly four orders of magnitude; on a linear
  axis the v2 line is flat against zero and looks like a bug rather than a result.
- One line per run, redrawn each second from the WebSocket.
- A vertical marker at the moment the eviction batch was dispatched, labelled.
- Samples with `ok:false` (timeouts) still plot, visibly distinguished.

## Controls

```
[ Measure legacy (KEYS) eviction ]   [ Measure hashed index eviction ]   [ Stop ]
```

Both run buttons are disabled unless seed state is `ready`; when it is not, show a `Seed fixture`
button and the progress instead. Disable the run buttons while a run is active, enable Stop.

## Status strip

Seed state and key count · run mode · elapsed · webhook job `processed / total` · connection state.

## Expected results, on the page itself

Put a short legend on the page so a visitor knows what they are looking at without the README:

> **Legacy (KEYS):** latency steps from ~1 ms to seconds on the first scan and stays there. The
> batch is not expected to finish — that is the point. Press Stop whenever you have seen enough.
>
> **Hashed index:** latency does not move. 1,000 users are invalidated in well under a second.

## Robustness

Auto-reconnect the WebSocket with a small backoff, and redraw from the `history` frame on connect.
A page refresh mid-run must not lose the chart.

## Self-check

Verify in a browser (use browser tooling if you have it; otherwise say so in `progress.txt`):

1. `make up`, seed, open `localhost:3000`.
2. Start the index run — chart moves, line stays flat and low, job completes.
3. Start the legacy run — line steps up by orders of magnitude within seconds.
4. Press Stop — polling halts and the webhook job reports `stopped`.
5. Refresh mid-run — the chart redraws from history.
