# US-005 — the deterministic seeder

## Why there are no data files in this repo

Ten million records is well over 500 MB as CSV. Even the 2M default is ~100 MB. None of that
belongs in git, and a fixture you cannot regenerate is a fixture you cannot trust. A seeded PRNG
costs zero bytes and gives byte-identical output every run — which also means the eviction batch
always targets users that actually exist.

Use a small deterministic generator (mulberry32 or xorshift is plenty — a handful of lines, no
dependency). Seed from `SEED_VALUE`, default `1`.

## What to generate

```
userCount   derived so userCount * averageVariants ≈ SEED_KEYS   (averageVariants = 2)
userId      "u_" + String(i).padStart(7, "0")
variants    1 + (deterministicHash(i) % 3)
planId      cycled deterministically over pro-monthly, pro-yearly, team-monthly, gen-ai-100k
```

For each user, write its 1–3 cache strings with `EX 3600` **and** the index set for that user
(`SADD` all members, then `EXPIRE ... NX`, then `EXPIRE ... GT`).

## Writing 2 million records without falling over

Pipeline in batches of ~20,000 commands. **Inspect every reply**: a load that silently drops half
its `SET`s produces a smaller keyspace, a faster scan and a demo that flatters the wrong thing.
On any error, abort and set `state: 'failed'` with the message.

When finished, assert `DBSIZE` equals the expected total and write a marker key
(`seed::marker` → JSON of `{seedValue, targetKeys, users, cacheKeys, indexKeys, completedAt}`) so a
container restart does not reseed. `POST /api/seed/reset` flushes and clears it.

## Progress

Emit `{t:'seed-progress', done, total, percent}` over the WebSocket at least once a second, and
expose the same via `GET /api/seed/status`. Seeding 2M takes roughly a minute; seeding 10M takes
several. Silence for that long reads as a hang.

## Self-check

```bash
SEED_KEYS=50000 make up
curl -s -XPOST localhost:3000/api/seed
sleep 30 && curl -s localhost:3000/api/seed/status | jq     # state: "ready", progress: 1
redis-cli -h localhost dbsize                               # matches status.cacheKeys + status.indexKeys
redis-cli -h localhost --scan --pattern 'entityIndex::*' | head -3
# Reseed with the same SEED_VALUE and confirm identical DBSIZE and identical sample keys
make typecheck
```
